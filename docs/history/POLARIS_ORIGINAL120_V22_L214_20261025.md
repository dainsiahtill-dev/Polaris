## 个人质量反例

ROOT 在无源码写权限、无外网的既有 K1 沙箱消费原生现成 ELF。首轮八组公开入口场景通过，包括整数分、预算阈值、退款关联与上限、重复编号、拒绝时旧文件不变、多月跨进程查询、空图和示例复现。

继续验证两个已识别假设，得到：

1. **原预算约束被破坏。** 同月公开执行 `init 100000`、`budget food 30000`、`init 20000`，第三条仍退出0，并把账本覆盖为收入20000分、预算30000分。原要求预算总额不得超过收入；认定失败不依赖强制某个特定退出码。首次偏差在目标 `set_income` 接受新收入时，随后存储正常保存了其结果，不是存储原子性失败。
2. **多类别海图遮挡数据。** 九个普通类别的实际 SVG 仍固定1000×700，第九类别金额在 y608–644，后绘图例覆盖 y596–688。ROOT 亲自查看实际 Chromium 截图确认遮挡；README 声称随类别增长而增高，与实际不符。该组 XML/金额检查通过，不能冒充可读性通过。

两轮共110次实际 CLI 调用，九帧截图、七种不同画面均亲自查看。前后25个产物文件和 ELF 没有改变；零外部源码修复、安装、编译、原生门禁或收据写入。观察进程和浏览器已退出；失败观察的捕获文件逐字节核对导出后经 KFS 释放，原始失败记录保留。

当前结论是 **ROOT quality FAIL**。海图具有真实港口、预算岛、支出路线、宝箱与图例，但视觉仅为基础示意，字号、路线文字、暗礁与岛的布局仍粗糙。

## 对机制的解释

QA 是同一候选的语义漏检。最终物理请求具有正确 QA 身份、六个只读/审阅工具，三次成功浏览器捕获的实际图片进入后续请求；最后一请求包含六张图片、三种不同内容。没有证据支持本次失败由缺少视觉、身份串线或候选绑定错误造成。图片送达不能证明模型实际覆盖了全部状态转换和布局规模。

最终多模态请求的实际视觉 token 与窗口占用明确 UNKNOWN；序列化代理不是实际视觉 token。全程146次逻辑 prepared，已报告输入399690、输出96142、合计495832 token；物理 POST 次数、账单和人工分钟仍 UNKNOWN。不能用上下文数量推算物理请求，也不能在失败项目上把单次成功成本记为零。

另外确认 Supervisor 的实例日志仍落在全局 `~/.polaris/instances/<id>/logs`，虽 SQLite/CAS 已在项目 `.polaris/runtime`。该用户要求的存储边界缺口没有在冻结运行期间热改；后续需要完成现有 layout/KFS、启动、前端恢复和日志读取的相邻迁移。共享实例发现 Registry 与项目运行数据分别具有已有明确 owner，不新建控制器或并行账本。

后续修复应把完整原目标和反例交回正式 Director＋独立 QA。已完成且验收有效的旧 run 的 resume 是幂等返回，不用于偷偷追加反馈；新的修复任务必须显式记为另一次人工反馈任务及新预算，不能冒充原身份恢复或原失败反转。目前仅准备，尚未启动。
