# Collection-aware Chief Engineer recipe recovery

PM contract and authenticated bindings → CE draft → existing verifier policy feedback → collection-aware diagnosis → current typed result schema → original canonical admission.

The CE owner validates recipes and reports their source collection/path, expected modality and policy-supported modalities/collections. Entrypoint profile mismatches request a full unaccepted draft revision using the existing recovery branch. Factory appends one server-owned guidance rule after its five repair objective builders.

Original PM/user requirements, accepted CE obligations and explicit command bindings remain immutable. A required flag in an unaccepted draft is model data. The model may correct, remove or relocate a diagnosed row only within the current result schema, preserving original required verification and real application entrypoint requirements, owners, identifiers and references. Profiles, hash binding, signatures, admission and execution authority are unchanged. No target effects or new repair engine/API are introduced.

Regression-first validation covers original rejected commands, a different language profile, explicit binding omission, fabricated hashes and local HTTP bad-collection→corrected portfolio with two sealed CE requests and unchanged PM hash. Native qualification remains a separate pending gate.
