# 保留能力、比较机制：当前实验与收敛顺序

状态：2026-10-22 的有界实验记录。平台总体能力未完成验收；长期记忆暂不做。所有选择服务于可复现的无人值守工程交付，不以代码数量、角色数量或规则数量判断先进性。

后续进展见[历史能力取舍与质量实验](../experiments/POLARIS_FEATURE_EVALUATION_20261022.md)：历史 174 项盘点、预审／DOM 消融、替代 QA 对照及冻结原生 r03 已完成。r03 的真实 QA 拒绝与自主修复成立，最终平台接受而根检查仍失败（近静止车轮、调速跳变），资源已关闭。随后合成组成实验验证了现有 K1 的只读计算与隔离，产品 QA 尚未接通；下一项是只读命令与候选版本接口及实际验收收益。下文保留前阶段实验与当时计划，不能把其“下一步”当作尚未发生的最新状态。

## 已核对的功能差异

PM 的需求分析、CE 的技术设计和 Director 的执行分工继续保留。当前 `EngineeringRunService.run_collaborative` 复用完成的 PM/CE 文本建议，再驱动同一 Director；它没有接入旧 TaskMarket 的工项发布、依赖调度、领取和租约恢复。旧模块仍存在不等于新产品已保留这些功能。恢复任务管理能力应复用现有边界，同时保持一个工程事实 owner，不能把模型维护的合同、hash、义务覆盖图一并恢复为前置条件。

上下文也需分开描述。当前工程循环从自身 SQLite 角色 frame 恢复 native 历史，经 K1 的预算与结构保护进入模型，继续保存真实 provider request 的 ContextOS 快照。它没有接入旧 StateFirstContextOS 的完整状态投影或 TurnEngine/TransactionTurn。通用文本压缩路径仍可条件使用 RoleContextCompressor。现有审计、上下文选择和执行恢复是不同能力，不能用一个名字概括，也不能拿两套不同执行底座做对照后把差异归因于 ContextOS。

## 已执行的实验

| 实验 | 真实观察 | 可以支持的结论 | 尚不能证明 |
|---|---|---|---|
| 原 TaskMarket 公共 API 与真实 SQLite | 两个合成工项发布；有效租约重复领取拒绝；原进程退出后冷续租和推进；真实到期后两进程竞争仅一个 CAS 成功；旧 token 拒绝，新 owner 继续，两项均到 `pending_qa` | 领取、排他和恢复是可独立运行的具体能力，应保留并进一步评估组合方式 | 当前新链路已接入、真实项目完成、交付质量或经济性更好 |
| 同模型、同任务和源码的视觉消融 | 两个原候选，四次独立真实调用，交叉顺序；每对实际请求去掉图片块后完全相同。静态 SVG 为 yes/yes；旧动画纯文本为 unknown，有图为 no | 文字已指出连接风险；真实图片帮助本例确认了腿与身体分离的可见缺陷。保留 Director 观察与独立视觉 QA | 总体可靠性提高、误批准率下降、最佳模型或最低成本 |
| 新回归的冷/暖因果控制 | 原外层 runner 禁止写 bytecode，同时指定空缓存，12 项在 HTTP 前超时；七组对照复现三类失败，同源码、断言和原时限下暖缓存 12 项全通过 | 测试环境造成反复冷编译，不能误判成输出预算或恢复机制退化。只修外部 runner 的环境继承，另起 r2 | 所有真正首次冷启动都满足 3 秒请求预算；原失败被改成通过 |
| 按模型上限的输出链路 | 原失败运行实际发出 3000；当前 M3 路由明确拒绝大于 524288，四角色完整 K1 路径真实发送 524288 并返回；配置/预算/最终 body 分别核对 | 修复忽略配置的默认值；最大生成上限不等于必须消耗或预留那么多 token | 新网页交付成功，或实际生成了 524288 token |

视觉消融共耗时 28.90 秒；TaskMarket 外部实验约 15.96 秒（包含 8.28 秒真实租约等待）。这是不同实验的耗时，不作性能横向比较。模型调用逻辑次数、准备/完成快照、HTTP 实际发送、供应商 usage 和实际账单分别记录；未知费用与发送数保持 UNKNOWN。

## 当前取舍

1. 保留专业角色与可读计划/设计。当前正式网页合同已要求先保存有用的简明计划、设计笔记，再实现；无需模型维护内部协议。
2. 保留真实执行、host 权限、单 workspace 写入者、耐久会话、取消/恢复、独立 QA、最终请求审计和单轨 WebSocket。对这些边界验证安全与合法推进，不以拒绝数量作为收益。
3. 保留原调度模块，明确新链路尚缺其工项能力。先选择一个实际行为做组成实验；接入前解决事实 owner 和重复状态问题，不能仅因旧模块局部通过就恢复整套旧链。
4. 原 TaskMarket 竞争失败方留下了一条未提交的 `claimed` Cognitive 收据（8 张收据、7 个已提交转换）。TaskMarket 状态仍安全；下游是否会误读 UNKNOWN。它是该组合边界的待查项，不是当前动画交付的新前置研究。
5. 原 120 项目录和历次 FAILED/CANCELLED/UNKNOWN 不改。已经失败的原生动画运行 `1be9405400f34a8aa5c3ff12cd692218` 保留 `failed/not_accepted`、零源码；旧动画 `a420e40bb7434b1e85bd50d2fbfadfcd` 保留平台通过、根视觉质量失败的区别。

## 下一步与停止条件

先结束当前输出默认值、空截断反馈、coverage 显示和相邻接口的验证，提交到 main，冻结源码、模型配置、任务与验收。随后用原协作合同全新隔离运行动画网页，由 Polaris 自己生成、修复和执行检查；Director 与 QA 各自观察当前候选，主 Agent 亲自检查实际画面、动画和交互，并核对资源闭合。外部不得代写目标、代装依赖、代跑项目验收或补造收据。

得到有效基线后，按预登记顺序比较 direct 与 PM→CE→Director。两臂使用字节相同的共同任务、模型、权限、每项目 5400 秒/外层 6000 秒、视觉 QA 和外部质量口径；一次只跑一个。共同任务必须先去掉原任务“固定 collaborative”的处理条件，保留全部可见质量和计划笔记要求，明确这是新实验合同，不能混作旧合同的重验。只改变现有 workflow，记录 Director 实际按需咨询，不人为禁用能力。先观察一个配对，结论不清才设计有理由的重复，不宣称一次实验找到了最优组合。

任务派发与 ContextOS 后续比较保持相同工程 owner、权限和恢复逻辑。ContextOS 当前没有可切换的选择策略接口；先以现有独立组件验证 native 工具消息、图像与引用完整性，再决定最小接入方式。长期记忆不加入这组实验。

每个问题只有一个假设、最小反例和有限实验。原失败可复现、修改改变了对应机制、相邻消费者与必要反例满足要求，就停止该主题并进入真实验收。与当前交付没有直接因果的新风险进入队列。用实际质量、交付率、合法恢复率、全部尝试耗时与成本、人工介入决定扩大、简化或保留；没有对照数据，不宣称优于 Codex/Claude。
