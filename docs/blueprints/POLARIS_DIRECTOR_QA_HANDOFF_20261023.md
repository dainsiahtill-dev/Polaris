# Director 与独立 QA 的视觉交接

状态：最小实现与组件资格完成，待main提交和全新冻结原生验证；尚未证明交付、质量或费用收益。基线 `cce3e862b90164ba60a235dc02cc2fdbbbc4e075`。

## 事实与问题

L1-05 v9 的 PM、CE 和 Director 已真实运行，Rust 编译器通过显式 host 工具链绑定可达。最近三组完整循环中，20 个业务文件和八份 SVG 的内容 SHA 未变，Director 仍在验证与视觉终检之间循环，独立 QA 没有开始。最新运行已取消，QA `not_run`、最终验证与结果 `unknown`；不能称为成功。

第一处交接偏差在 `EngineeringRunService._verify_director`：当前检查通过后，必须先满足 Director 当前 frame 的图像输入，才能进入必需的 QA。模型重复复制输出或执行可写预检使候选验证失效；再验证产生的新 frame 又没有当前图像。合法的仅截图下一步仍存在，故未证明机械死锁。原始证据在目标项目 `.polaris/audits/independent-v9-convergence/report.json`。

## 有界假设与选择

假设：当 host 已要求独立 QA 时，Director 当前 frame 图像不是“交接给 QA”的必要条件；QA 自身的当前源码、有效检查、同候选视觉与最终物理请求校验足以保持独立验收边界。可允许模型自主选择视觉时机，减少重复交接。

比较三种办法：保留现状继续提示（已有连续无业务变化反例）；跨 frame 放宽图像 freshness（会改变所有视觉证据语义，范围更大）；仅取消必需 QA 前的 Director 重复视觉门禁（最小候选）。选择第三种做实验，不以单个路由实验宣称质量提高。

## 数据流与职责

原目标及 PM/CE 建议 -> Director 原生工具与反馈循环 -> 当前真实检查 -> 必需独立 QA -> 同一候选验收。没有必需 QA 时，现有 Director 视觉终检保持。

唯一状态 owner 继续是 `roles.runtime` 的 `EngineeringRunService` 与工程 SQLite。迁移同一交接的不同行为消费者：`_verify_director` 决定实际交接，`_fresh_verification` 决定 snapshot/observe/冷读当前验证，`run_engineering_loop` 从既有持久 require_qa 传给 `role_instruction`，让模型提示与实际条件一致。不新增持久字段、host 配置、控制器或 ledger；内部提示参数默认保持旧语义。Director 保留 `browser_observe`、图片输入与自主修复；QA 的源码读取、当前截图、物理请求图片、候选绑定与拒绝反馈均保留。权限、期限、原始检查、显式空授权、恢复和未知效果不变。

## 实验、反证与接受标准

1. 冻结基线，七个有界模块场景用真实 Store/Verifier/隔离命令；只替换模型、QA 到达 spy、继续执行 spy。A 原实现与 B 最小处理面对同样 Director 输出、源码和通过检查。只记录 QA 是否可达，spy 不返回 approved。
2. 反例：无 QA 仍须 Director 视觉；缺失/失败检查不能进入 QA；QA 未读源码或缺当前图像的 report 必须拒绝。
3. 若 B 不能进入 QA、绕过 QA 图像/源码要求、错误接受失败检查或改变权限，推翻假设并停止集成。若仅路由可达，不证明真实模型收敛或质量提升。
4. 写生产回归先见 RED，再做最小实现并见 GREEN；相邻验证/QA/恢复/视觉测试、Ruff、mypy、架构与必要发布检查通过，独立审查后集成 main。
5. 新源码与配置冻结另开批次，用正式全新隔离项目验证实际 QA、质量、请求数、耗时与资源。旧取消结果保留；个人独立质量检查不得写目标源或补造验收。
