# ContextOS 每轮决策所需的上下文

设计决定，2026-11-25。适用范围为 EngineeringRunService 的工程循环。目标是减少没必要的上下文，用蒸馏器、吞噬兽、制图师增强受限模型做工程判断的能力。交付终点是给定目标后全程无人介入，真实产物被独立接受，可由第三方复核。

## 为什么需要改底座

在批次 `c26eb4cc949d47cf89724710ef6f9fa2` 的 L1-01，MiniMax 的两个验证事件 865、917 都含有 exit 0 的 npm test 回执。同一份 TAP 输出把失败数写为 `# fail 0`。宿主把这行提取成未解决失败，两个候选累积四次。物理请求快照 `c262decf34a1231d3c89fed4` 的 system 字段要求模型解释这个“反复出现”的故障。阶段卡还在 QA 请求中建议交给 QA。删掉几十个 token 的错误指令，比压掉几千个 token 的真实证据更有价值。

同一项目的 `epoch-0041-0050` 只从第 50 轮构建输入，却把覆盖范围标成十轮。此前九轮有已观察到的写入和编辑。快照 `3854f13c1ac15cc5ae7c158e` 包含“no source files were changed”。蒸馏器另有两处静态可复现的风险：同路径不同快照可以共用摘要，单节点摘要收到同批以外的命令引用。三者都涉及证据的适用范围。这里的物理请求来自既有运行，不能证明新代码的交付效果。

## 选型与所有权

选择在现有 roles.runtime 内统一编排每轮请求。三条独立注入链改动最小，但无法统一处理角色冲突、重复和总预算。另设一个模型负责裁剪全部上下文，会占用关键路径预算，并把判断哪些事实可见的责任交给另一个受限模型。

EngineeringRunService 仍是唯一工程 owner。workspace 内 sessions.sqlite3 保存原始工程事实，ContextOS 留存最终物理请求。复用 working_state、phase_policy、evidence_graph、tool payload projection、既有 semantic contracts 和恢复工具。每轮的决策输入是现有日志的只读投影，可以随时销毁并重建。三兽各自产出局部建议，共享调度和录取边界，不派生新的工程运行。

## 一轮请求怎样生成

1. **冻结事实边界。** 在同一读取视图确定 workspace、run、当前 role/frame、候选绑定、journal 截止 seq、宿主允许的工具和剩余预算。先从已配对的 dispatch 和 observation、verifier 与 QA 的当次回执派生已知结果。中断、失败、未观察和已被后续验证解决分别记录。原始 stdout、源码、页面内容与模型文字均保持数据身份。
2. **确定此轮要做的判断。** 取现有阶段策略、本轮动作、上次失败和未解决的用户条款。Director 编辑时需要当前目标片段、接口与最近一次有效反证。QA 需要原目标、当前候选、逐条可重做的探测与证据缺口。PM/CE 咨询使用自身只读范围。验收要求全部保留，摘要可以帮助定位原条款。
3. **选择最小充分表示。** 固定保留角色身份、授权工具及 schema、必要产物/验收约束、当前操作依赖、native tool 的调用结果配对和输出余量。每个内容节点按“原文 / 精确切片 / 可核摘要 / 可恢复引用”选一份。相同版本和覆盖区间才可以去重。模型正编辑的内容、未解决错误和独立 QA 判断所需原证优先。恢复工具须已获授权且能在该 workspace 取回绑定版本；只能取得当前文件时明确区分。必须内容装不下时，先尝试按当前动作切片；仍超窗则暴露具体缺口，不捏造完成状态。
4. **按需增强。** 只有可说明“辅助哪项判断、为何此时值得”时才入队。总预算包含主模型与三个辅助模型的调用、token、时间和重试。先为 Director 和独立 QA 预留，剩余预算竞争当前最有价值的一个任务。相同输入和契约版本共用已验证结果。在途结果不会阻塞角色请求；迟到时复核快照、证据范围及角色。无可取建议时，当前轮仍有宿主事实及授权恢复路径。
5. **只投影一次。** 原始材料留在日志或快照。每轮在 native 编码之前按角色生成完整、自足且有界的决策输入。稳定身份与动态数据分层，模型建议按不受信任的数据渲染。已发生的作用不能由建议改写。编译完后的 provider 适配层负责协议配对、图像计价和最终窗口检查。
6. **从物理请求核实到达。** 用已有调用身份和 context_snapshot_ref 对照 final_physical_request.body 的实际字段、工具和语义片段。采用 Anthropic 合并 system/text block 后的位置及 OpenAI 对应位置。生成、录取、编码到达和下一步有证据的动作分别计数；一次调用的前后快照不能重复计为两轮。缺 post-capture 时暴露 UNKNOWN。模型复述建议仅说明复述；因果收益需要配对实跑。

## 三兽的输入、输出、失效条件

| 辅助角色 | 何时值得调用 | 给模型的帮助 | 裁剪或失效条件 |
|---|---|---|---|
| 蒸馏器 | 大块已观测内容即将退出焦点，模型仍需理解它 | 针对具体文件切片或命令输出解释接口、行为、关键限制，保留可恢复引用 | 每条建议绑定平面、节点、精确快照、所见区间。仅接收该节点的证据；快照或区间不符就使用宿主原文、切片或结构摘要 |
| 吞噬兽 | 一段工作已闭合，旧历史即将退出，但下一阶段仍依赖此前尝试 | 保留尝试、结果、已排除的假设、未解决问题与下一次有区分力的检查 | 宿主按真实 turn 边界汇总完整区间和已观察效果；缺失区间明确留白。模型解释逐项引用；在单个 epoch 未观察到某项，不得推出全项目从未发生 |
| 制图师 | 多个可行下一步互相竞争，阶段发生变化，或最近动作没有消除故障 | 根据一个明确的不确定点，给出下一步建议、可观察的预期及关联证据 | 角色、候选、阻塞或未满足条款变化后重新选择。Director 的修复建议仅用于该 Director。QA 使用独立审查视图和原证；模型无权更改阶段、验证结果或验收 |

各辅助输入只携带它需要读的材料。证据引用的允许集合仅限实际随该输入给出的内容。引用合法仍不能证明叙述正确，故可机械检验的字段由宿主渲染，推断保留来源、覆盖范围和不确定性。收录一条建议时优先替换它概括的冗余材料；保留原文与摘要两份时，应有当前决策或恢复方面的理由。模型指出某条建议误导时，保存原观察与后续效果，不把先前结论覆盖成正确。

### 评估怎样区分宿主与三兽各自的收益

预注册一个新实验，登记本次规程、源码及模型路由的摘要和原始资源上限。开发集比较三个条件：现行整套系统、新宿主且关闭三兽、新宿主且开启三兽；在新宿主上逐个移除一只兽，记录交互效应。离线从相同事件截止点重放，可以发现遗漏、错绑和无效字节。它不能回答模型下一步会做什么。该问题用干净 workspace 配对实跑，冻结预算包含三兽消耗和异常退出。用同一候选做独立审查，审查方不知试验臂。模型推断、证据选择或下一步命令恰好一致，都不能直接记为一次成功交付。

建议在计算量明确后、看到该组结果之前冻结重复次数。开发集每项目每臂先做三次，报告每次而非取最好成绩；正式确认覆盖固定目录的全部 120 项，重复次数、并发与总预算在正式开跑前登记。按项目配对汇总，报告接受率差的 95% 区间；要声称“提高交付能力”应观察到正提升且置信下界大于零。要单独声称“更省”还须报告在预注册可容忍退化幅度内的交付结果及实际成本差。虚假验收、关闭必需门禁、跨角色或跨候选授予成功均阻止切换；能力不确定时保留对照和未决结论。费用取 payer 账单；供应商不披露时保留 UNKNOWN，另列可取得的用量。

恢复历史运行时，原日志和旧物理请求可查。用于**下一轮**的事实视图要按原始事件重算；缺少输入绑定、完整轮次或读取权限的旧摘要不再作为现时依据。event 序号给审计员定位 journal。给模型恢复原始证据时须另外检查当前角色可用工具、实际版本引用及可取回性，必要时在当前预算内附关键片段。

## 本轮实现与证据边界

现有 `load_projection_inputs` 在一个 SQLite 读事务内固定运行和 journal 前缀。蒸馏、吞噬、制图、失败聚类和角色工作状态复用这次读取。准备事件记录 `context_input_seq` 供重放；这个序号定位宿主事实输入，最终请求仍以 ContextOS 的物理 body 为准。渲染阶段统一编译 Director 的可选建议，用已有 trailing user 消息承载，并和原生历史一起计入预算。QA 使用自己的角色与候选证据。窗口不足时比较去除建议后的方案，优先保住必要的图像与工具观察。

使用 L1-01 截至事件 1241 的同一前缀序列回放 60 个 Director 轮次。与主仓基线 `517a7d88b` 的记忆构建器相比，仅记忆段的累计 UTF-8 字节从 78,880 降到 71,287。其中误报“# fail 0”的轮次从 4 降至 0，嵌入维护说明的轮次从 34 降至 0。该对照只测请求编译的一段，不测 token、费用和工程能力。旧运行中以有效结果落盘的 179 条节点摘要属于 8 组节点、快照与行范围。新选择器可跳过已经处理的相同输入并覆盖其它候选。受控物理请求覆盖两种协议中的当前建议、过期建议和独立 QA；它们使用测试 provider。真实新版本的独立交付收益待测。

制图师在七个历史调度点中有四个属于当前允许的 Director，另外三个属于 QA。四个 Director 输入从 12,917 降至 8,985 UTF-8 字节，减少 30.4%。输入包含目标节选和带出处的实际操作。无关事件不改变这些输入的指纹。至事件 1241 的真实 Director 请求分为 57 次 build 和 3 次 verify；两阶段在新版受控请求中可区分，模型给出的认知焦点单独标注。这些数字分别描述制图师输入和宿主阶段分布，与 Director 记忆段采用不同分母。

三兽的跨运行总费用上限、按实际剩余资源竞争的调度和 L1–L12 配对收益仍在迁移范围内。当前 role 内可去重及已有单并发插槽不能证明全局计费或调度策略已经实现。

## 效益假设与否证条件

旧 L1-01 的 60 个 Director 终态请求中，35 组不同的 `write_file` 调用标识与正文共出现 1,033 次。只数正文，累计 3,995,072 UTF-8 字节，其中 1,107,639 字节出现在同路径已有后续成功写入或编辑之后。修改前版本有时仍有诊断价值，故后者是可检查的旧载荷上界。策略优先从重复携带的旧正文入手，保留当前编辑所需切片、精确差异和可恢复的历史引用。旧运行主模型累计报告 3,799,945 个输入 token，其中 1,556,321 个报告为缓存读取。分别量首 token 等待、输出吞吐、主辅模型排队、工具耗时及总交付时长；只减少字节无法推算延迟。

可证伪预测分两层。第一层，确定性选择当前版本、隐藏旧输出，应减少上下文占用且维持当前任务所需原证。第二层，加入三兽后，相较相同的确定性宿主，弱模型应减少为理解同一版本而额外支付的重读、重复失败或无效编辑，并提高固定预算下的独立交付率或在同等交付率下缩短总耗时。若辅助建议只是在每轮增加一段解释、没有替换任何材料或改变有效动作，停止为该场景调度。纯压缩的“摘要已生成”和纯建议的“建议被照做”均不能作为提升能力的判据。

因果测试先冻结历史决策点及其之前的证据；在互不影响的候选副本上，对同一弱模型、同一合法工具集和生成预算，随机或交替发送“宿主事实”或“宿主事实加对应辅助”。独立检查下一至数步能否取得预定的判别性证据，保留有效替代解法并记录额外工具轮次。仅作机制筛选；正式评价回到完整项目、固定总成本和独立验收。短任务与长任务、冷缓存与热缓存、失败诊断与正常编辑分层报告，防止平均值掩盖逆收益。

SWE-agent 在 SWE-bench Verified 上已有观测遮蔽与摘要的对照，简单遮蔽取得强基线，混合策略在该设置下进一步省成本。Polaris 需对自己的任务与模型重复验证。[原始研究](https://arxiv.org/abs/2508.21433)
