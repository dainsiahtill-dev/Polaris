# QA 独立检查：只读执行与当前候选

日期：2026-10-22。源代码已实现，组件验证完成；真实模型的验收收益尚未验证。本轮没有修复历史网页产物，也没有取得新的动画网页交付成功。

没有重启受保护的主服务。这里的执行证据来自隔离测试进程；主实例运行时是否加载新实现尚未验证，后续模型和项目证据须绑定新的冻结候选。

## 问题与基线

冻结原生 r03 `b713cc21a2bd4c33995f63851a6bfe6f` 经实际验证和独立视觉 QA 被平台接受，主 Agent 检查原字节网页后仍判质量失败：车轮近乎静止，调速改变倍率和暂停姿态。原生 accepted、根质量 FAIL 与资源已释放三个事实均保留。完整源码与 21 张 QA 自己截取的图片实际进入过请求，不能把漏验简单归因为输入缺失。

前一轮额外预审和完整 DOM 转储没有解决核心漏验。替代模型找到了旧缺陷，却仍在 r03 漏验其它运动错误。下一项假设是：让 QA 自行构造和运行独立检查，可能改善判断；工具可用本身不证明这一收益。

修改前基线为 `main@a58f6ac32c216ecbd6288ffb5496606089c4d6fc`。现有 K1 合成实验已证明只读候选、私有 tmpfs 与网络隔离可以合法推进；当前角色策略却排除了 QA 的 execute。源码与真实反例还显示，单独开放工具不够：所有命令都会使候选版本变化、清空验证；当前权限在模型调用期间被撤销后，普通命令及后续正式检查仍可能使用旧授权。

## 修改机制与状态所有权

仍由现有 `EngineeringRunService` 和 workspace 内的 `engineering/sessions.sqlite3` 拥有工程状态，工具经现有 ToolSpec、KFS、K1 sandbox 和进程 owner 执行。没有增加控制器、任务表、结果账本或模型维护的交接合同。

1. QA 只在 host 已授予 `execute_command` 时获得该能力；角色作用域继续强制空写入根和禁网。PM／CE 不获得命令能力，显式空权限仍为空。
2. QA 可在单次命令的私有临时空间构造检查，候选与依赖保持只读。临时文件不跨调用保留；不能把检查程序 exit 0 和被测效果成功混为一谈。
3. 候选失效依据实际交给 sandbox 的作用域：无写入根且禁网的命令保留当前版本；可能写入或联网的命令继续保守地使验证失效。命令文本、角色自述不决定“只读”。当前源码绑定和 QA 前后输入比较保留。
4. 服务内原生工具与最终验证在归一化后、实际效果之前，复用原 owner 的当前策略检查。执行上限仍是保存的原授权，不能用当前更宽策略替换。撤权拒绝下一效果，不承诺追溯取消已在运行的命令。无动态 resolver 的显式组件只有其静态授权。
5. 取消、未知效果、耐久提交和恢复语义继续由原 owner 处理；即使命令被限制为只读，缺少耐久观察时也不能盲目重放或认定完成。

生产修改限于 roles.runtime 的五个既有实现文件：`engineering_roles.py`、`engineering_tools.py`、`engineering_loop.py`、`engineering_verification.py`、`public/engineering_service.py`。同步两份新测试、三份相关旧测试的语义、Cell／catalog 测试声明及说明。技术 public DTO 与描述器公开能力未改变，未运行会遍历并覆盖全仓资产的生成器。

## 实验与反例

模型端使用明确标注的合成回复；HTTP、原生请求编解码、真实工具、OS sandbox、SQLite 和恢复路径保持真实。它不能证明模型自主选择了有效检查。

| 问题 | 修改前 | 修改后与反例 |
|---|---|---|
| QA 独立计算 | execute 明确被禁用 | OpenAI、Anthropic 实际请求均包含 QA 只读命令；私有代码计算 `[3,5,8]` 得 16 |
| 产物保护 | 组件底座可表达只读 | QA shell 写候选收到真实 `errno=30`，原字节不变；PM／CE 命令和空授权仍拒绝 |
| 当前候选 | 只读命令也把 revision 从 0 变 1 | QA 计算及拒写之后，版本、实际验证、当前独立验收和冷读取一致；联网作用域的对照仍失效 |
| 当前授权 | 撤权后普通命令仍产生文件；第一项正式检查后撤权，第二项仍执行 | 下一调用明确拒绝；第一项真实结果保留，第二项无进程执行／退出码，不伪造普通测试失败 |
| 提交与恢复 | QA 无实际命令效果可供检验 | 真实 QA 命令已返回 49 后，仅在提交观察的口注入故障；新进程恢复保留 pending／UNKNOWN，没有新增进程或模型端请求 |

RED3 的四项机制失败和一个合法对照、初期测试夹具错误、恢复测试过严断言及修正前结果均已封存，没有把旧失败改为通过。旧测试不再把“只读”定义成“禁止所有计算”，仍检查真实写入拒绝、原授权身份、实际验证与无重复执行。

## 接受标准与下一步

本轮关闭的是 QA 只读执行、候选失效与授权的相邻接口，尚未证明最终质量改善。若命令未实际执行、候选可写、旧验收可套用到变更输入、撤权后仍有效果或恢复重放，当前机制解释即被推翻。

下一步使用相同失败候选、原任务、同组图片、模型和预算做有界比较，仅改变 QA 是否获得只读执行。需要看到 QA 自主选择检查、实际执行并据结果发现真实缺陷；仅工具成功、回复 no 或测试数量不能证明收益。公开角色入口尚无通用图片附件字段，实验的共同附件输入 producer 必须标明为模块替身，不能伪造独立截图或正式交付。

随后仍需全新隔离的原动画网页，由 Polaris 自己实现、修复、验证并接受当前独立 QA，再由主 Agent 亲查画面／动画／交互和资源闭合。历史失败不改写，原 120 项尚未因此完成；最佳角色组合、ContextOS 选择策略收益、长期稳定性和经济性继续待评，长期记忆暂不做。
