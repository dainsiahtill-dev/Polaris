# 历史能力取舍与质量实验

日期：2026-10-22。研究记录，不是平台运行事实源。先完成了[历史全特性盘点](../history/POLARIS_ALL_FEATURES_INVENTORY_20261022.md)：174 条记录、21 类、176 份不可变 Git 原文；历史设想、组件和当前能力分别标注。本文讨论取舍，原盘点不回写为“所有功能均已验证”。

## 当前判断

简化模型维护的合同协议，不等于删除专业分工、派发、恢复、上下文管理和独立验收。一个能力是否保留、当前是否接通、是否已证明改善交付，是三个不同问题。现有有效能力在比较前继续保留；尚未接通的历史机制先做限定组成实验。没有结果，不宣称最好，也不因暂时没有收益就删除整类能力。

| 能力 | 当前处理 | 证据与下一项问题 |
|---|---|---|
| Cell、KernelOne 与唯一工程 owner | 继续复用 | 新工程与真实工具已经使用；不恢复另一套控制器或写账。尚未证明比其它底座更优 |
| PM 需求规划、CE 设计、Director 执行 | 保留角色及可读工作材料 | 当前协作链已运行；尚无同预算完整项目对照证明最佳组合。下面的后置评审实验不能替代这一比较 |
| 派发、领取、依赖和租约恢复 | 保留旧公共组件，候选接入 | 真实 SQLite、两进程竞争、过期 token 拒绝和冷恢复实验已做；新工程尚未接通。须避免两个状态 owner，不能恢复重型准入 |
| 当前会话、执行事实、取消与恢复 | 保留并持续验证 | 当前工程 SQLite 是唯一事实 owner；旧 TurnEngine/TransactionTurn 的全部语义不因此自动等价，也不整体恢复 |
| ContextOS 最终请求审计 | 保留 | 已据实际 body 排除本次 QA 源码、图片缺失的解释；这证明可观测价值，尚未证明提高交付率 |
| ContextOS 选择与压缩策略 | 单独研究，暂不整体接旧链 | 旧独立组件的 native 消息和引用适配仍有差异。比较时保持相同执行 owner、模型、权限与恢复，仅改变上下文选择 |
| 工具归一化、权限、真实路径和隔离 | 保留必要边界 | 模型可自然调用，授权仍由 host 决定。合法推进与拒绝非法效果都需验证；拒绝数量不是收益 |
| Director 浏览器观察与独立视觉 QA | 保留，补测遗漏 | 旧动画看图可识别腿与身体分离；新动画看过完整源码与图片仍漏验，接口存在不等于有效验收 |
| 额外 CE／QA 预审 | 按需能力，不新增强制门禁 | 本轮没有解决脚与曲柄漏验；CE 同时发现了一处真实源码缺陷，不能据此删除 CE |
| 模型路由与输出预算 | 保留按模型真实上限的修复 | M3 实际请求上限 524288；上限不是实际消耗。模型费用与物理 HTTP 次数缺证据则 UNKNOWN |
| 实时进展、Launcher 与资源生命周期 | 保留 | 沿当前单轨 WebSocket、独立实例和资源 owner 继续验证，不用内部 Bench 数据替代生产事实 |
| 确定性专业修复、代码智能、MCP／Skill 等 | 保留可选能力，逐项比较实际收益 | 普通工程失败仍回原 Director；不把所有旧能力自动插回主循环，未实验项目继续待评 |
| Plan DSL、群体共识、认知／Resident 自我改进 | 暂不引入当前交付循环 | 历史设计或局部实现不证明当前项目收益；没有直接因果证据时不增加当前前置条件 |
| 长期记忆 | 暂不做 | 用户决定；仅保留历史盘点 |
| 内部 Bench 与评测量具 | 保留测试用途 | 所有分配、失败、未知和资源结果保留；不提升为产品控制面 |

这些是当前处置与待验证范围，不是 174 条特性的最终排名。

## 已完成：额外预审是否修复 QA 漏验

同一模型、当前角色提示、完整原始任务与源码、同组实际图片，比较三种策略：一次 QA；源码 QA 预审再视觉 QA；源码 CE 预审再视觉 QA。两种双次策略各六次逻辑调用，一次 QA 策略三次，共 15 次，144.97 秒。随机化候选顺序并轮换策略顺序；独立会话、无替补或自动重试。实验私有配置仅将 M3 retries 改为 0，生产配置未改。

实际最终请求逐对核对：预审除角色 system 外一致，终审除匿名预审意见外一致。完整源码和图片字节均在实际 body 中。根 Agent 先封存九份匿名终审回答的语义判断，再读取策略映射；已知候选和回答措辞可能泄漏信息，不能称完整双盲实验。

| 候选 | 一次 QA | QA 预审再 QA | CE 预审再 QA |
|---|---|---|---|
| 旧动画：身体与腿脱离 | no，发现核心缺陷 | no，发现核心缺陷 | no，发现核心缺陷 |
| 新动画：脚与可见曲柄约 90° 错位 | unknown，未发现核心缺陷 | yes，漏验 | yes，漏验 |
| 历史静态 SVG | yes | yes | no，发现真实重复 ID |

新动画的一次 QA 以缺少历史执行记录为由给 unknown，同时肯定了错误的共享坐标解释；它没有误批准，但也没有提供有效核心修复反馈。不能把 unknown 直接记成正确诊断。

静态样本确有 `linearGradient` 与 `g` 同为 `id=frame`。这违反 [SVG ID 唯一性要求](https://www.w3.org/TR/SVG/struct.html#Core.attrib)。保留旧的可见任务足够评价，但撤回其“无缺陷正例”解释；不能把 CE 拒绝盲计为误报。跨渲染器的实际影响仍 UNKNOWN。

| 策略 | 逻辑调用 | 调用耗时之和 | 供应商报告 total tokens |
|---|---:|---:|---:|
| 一次 QA | 3 | 32.42 秒 | 39916 |
| QA 预审再 QA | 6 | 28.25 秒 | 69996 |
| CE 预审再 QA | 6 | 71.81 秒 | 76624 |

两次调用策略并非与一次策略等计算量；usage 也不等于实际账单。实际物理 HTTP 次数与费用 UNKNOWN。三份相关候选、每策略一次抽样不支持总体可靠性、经济性或最佳架构结论。

本组只研究**完成产物之后**的 CE 源码预审，不能推断**编码之前**的 PM 规划／CE 设计对 Director 的贡献。当前结果支持保留专业审查能力，不支持新增额外 CE 必经门禁；也不支持删除 CE。

## 已完成：通用渲染几何信息消融

当前 QA 已有完整源码和原生图片，却没有得到 SVG 元素的实际屏幕变换与几何数据。假设：通用渲染观测能帮助模型区分源码中的共享变量和实际可见关系。

比较相同 QA、模型、完整源码和四张 PNG：A 不附加 DOM；B 仅附加所有 SVG 图形元素的几何、矩阵和时间数据。三例共六次独立调用，无重试替补，600 秒总预算；标签、根诊断、特定元素距离或角度不能进入输入。截图与 DOM 非原子同帧，必须保留各自时段。用另一份 ID 唯一的历史静态 SVG 作局部正例，不修改原候选来制造正例。

六次调用已完成，共 47.80 秒；无失败、重试或替补。三对实际最终 body 扣除 DOM 块后规范化 body 内容一致；源码、QA system、温度、524288 输出上限及四张 PNG 字节和顺序均核对。53 份冻结文件未变。根 Agent 先封存六份匿名回答的语义判断再解盲，已知候选和部分回答措辞的泄漏限制仍适用。

| 候选 | A：源码和图片 | B：相同输入加全部 DOM |
|---|---|---|
| 旧动画身体／腿脱离 | no，发现核心缺陷 | no，发现核心缺陷 |
| 新动画脚／曲柄错位 | yes，漏验 | yes，漏验 |
| 另一份历史静态 SVG | yes | yes |

新采样四帧的实际几何仍复现 89.994–90.006° 错位；这些根计算只用于隐藏评分核对，没有进入模型输入。B 每帧完整覆盖 81／80／124 个 SVG 图形元素，无遗漏和采样异常，不能把结果解释成“根本没有给模型数据”。

A 三次调用的报告 total tokens 合计 42235，调用耗时之和 13.29 秒；B 为 531962、29.51 秒。报告 token 约为 12.6 倍，未获得本组增量核心缺陷检出收益；这是供应商 usage 和本次调用耗时，实际账单／HTTP 次数仍 UNKNOWN，不能外推总体经济性。

停止这项全量转储实验，不把它作为已证明的修复引入产品。这不否定按需 DOM 查询、主动计算或独立可执行检查的价值；它们尚未在本组研究。额外预审和全量 DOM 转储都未解决当前漏验，下一步候选是恢复 QA 的独立可执行检查能力，或比较已配置的另一视觉模型，先核复用与可行性再选择一个有限实验。当前没有因此扩展 QA 权限或修改产品代码。

## 后续候选的可行性与首个失败

独立源码核对显示，现有 EngineeringTools／K1 可表达只读候选、禁网和私有临时命令执行；当前 QA 的 role scope 则没有开放 execute。现有 `verify_project` 仍有 Director 角色守卫，直接借用不能冒充独立 QA。外部可写检查目录也不能原样挂入候选 workspace 的授权；需要先在明确标注的私有合成夹具中验证合法推进。保留这项原能力的候选，不恢复旧 QA 合同／broker 链，不建立新控制器或事实表。

更小的第一步是复用已配置的替代模型。DeepSeek 的[视觉说明](https://api-docs.deepseek.com/guides/vision/)与 [Anthropic 兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/)提供图片请求接口依据，原有 exact route 文本探针成功不等于当前账户图片请求成功。筛查保持 DOM-A 原任务、全部源码、四张图片、QA system 和温度，仅改变模型路由及其 393216 输出上限；固有推理、图像预处理和跨时段差异不能算架构因果证据。

第一次筛查 `qa-model-screen-01` 约 32.08 秒结束，无回答。外部脚本只给总 deadline 300 秒，没有显式设置独立的单请求 timeout，命中了既有 30 秒默认。原失败保留，模型判断 UNKNOWN。两份 prepared／timed_out 请求体真实存在且输入核对有效；原脚本 terminal 枚举漏掉 timed_out，导致 controls 为空，这是审计投影局限，不是请求快照丢失。原错误响应的零 usage 不能冒充零消耗。

无模型对照复现：总预算 300、无单次设置时仍为 30；显式单次 300 时受剩余总预算约束；总预算 30 时显式 300 也只能得到约 30。修改归属外部筛查 caller，不据此声称平台缺陷。另起 `qa-model-screen-02`，只修预算传递与 timed_out 证据投影，仍一次调用、总计 300 秒，不修改生产配置。

第二次请求在 250.55 秒后有效完成，实际 body 与第一次相同；相较历史 M3 DOM-A，仅模型与输出上限不同。DeepSeek 明确推导 `foot=BRACKET+30(cosθ,sinθ)`，可见曲柄端点为 `(32sinθ,-32cosθ)`，指出 90° 相位错位，并指出 smoke 只读自报数据、没有比较可见端点。根 Agent 和独立审阅均确认核心诊断符合原产物。附加结构和美学批评未全部背书。

这使“按角色配置不同模型”成为值得继续保留并验证的现有能力，当前无需先增加角色或几何转储。它只有一个样本，不是模型排名：推理与计算量、图像处理、请求时限和跨时段因素均不同。原 30 秒失败不改写；当前全局 QA 仍未因此切换，目标也未修复。随后先以原历史静态正例和旧动画失败作同一模型的保留对照，再决定全新原生工程候选。

两个保留对照已按预登记顺序完成：静态原任务为 yes（10.35 秒）；旧动画为 no（149.53 秒），具体指出身体／腿分离。两份实际请求都核对源码、四张原图、QA 身份、同模型及参数和冻结状态。它支持作为下一份原生运行的候选，不能证明一般误批准率；静态正例也不是已知优秀动画。

本次报告的归一化 usage 不能直接作完整输入账单：raw 包含 `cache_read_input_tokens=15744`，归一化 `cached_tokens` 却为零。保留两套原值与这个统计缺口；没有真实账单，不声称替代模型更便宜。
