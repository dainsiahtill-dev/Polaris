## Architecture Amendment A1: V1 evidence and pre/post-seal identity completeness

Two independent reviews found that the unshipped V1 public policy snapshot
retains only an aggregate `target_state_hash`. That aggregate is
information-insufficient for stateless revalidation: a changed
`agents_policy_hash` cannot be distinguished from target-content/stat/canonical
evidence drift. No snapshot-bound target-state evidence exists elsewhere, so a
comparison against a hidden cache or a parallel V2 contract would create a
second authority or unreleased debt.

Amend unshipped V1 in place. `DirectorEffectPolicySnapshotResultV1` carries one
immutable `baseline_target_state_evidence` using the existing public
`DirectorEffectTargetStateEvidenceV1`; its aggregate hash is derived from, and
validated against, its canonical components and is never a second authority.
The result also retains the exact typed `DirectorEffectPolicyOperationSubjectV1`.
The snapshot `evidence_hash` domain-separately binds every subject field plus the
complete baseline evidence. Inventory ordinals are TaskRuntime's zero-based,
non-negative values, so ordinal `0` is valid.

Pre-seal subject facts and post-seal identity are deliberately distinct.
`bind_member` compares the retained subject's ordinal, tool-call id, normalized
tool, effect type, execution mode, and prospective operation hash with the
actual sealed member and all three operation commitments. `effect_id` and
`operation_id` are generated by the TaskRuntime seal and are not guessed or
pre-authorized by Task 3. The authority chain is intentionally acyclic:
snapshot first, then authorization with
`bound_policy_snapshot_hash=snapshot.evidence_hash`, then bound snapshot with
the snapshot, `authorization_evidence_hash`, and complete sealed member. The
domain-separated `member_binding_hash` binds all three. Revalidation requires
exact bound-member, authorization-anchor, grant, and operation consistency. No
code attempts to recover plaintext identity fields from an aggregate hash.

`hash_director_effect_authorization_evidence` is the public, domain-separated,
UTF-8 canonical hash of every authority-bearing authorization field except the
digest itself. `DirectorEffectAuthorizationEvidenceV1` validates that digest at
construction. Task 3 recomputes it before any target observation, policy call,
or effect entrypoint, including for constructor-bypass objects, and returns
`deo_authorization_evidence_drift` on mismatch. This proves integrity of the
bound role-policy, tool-spec, allow-list, envelope, scope, Job Token, snapshot,
target, operation, and policy values against the trusted snapshot producer and
the authorization hash retained by the bound snapshot. Deterministic hashes do
not authenticate a wholly replaced in-process object graph; Task 3 makes no
such claim. It also does not claim current freshness for
role/tool-spec/allow-list/envelope fields because Task 3 has no authoritative
current source for them. Task 4 creates and compares baseline evidence only.
Freshness comparison is a Task 9 prerequisite and may occur only after claim
through the single versioned current-evidence producer frozen by A5. No new
authority input is invented.

Revalidation first validates the authorization digest and exact bound-snapshot
authorization anchor, snapshot digest, member-binding digest, retained
subject/member relation, and request/member/operation/grant static identity.
Any failure returns before target or AGENTS access and before a policy call.
`DirectorEffectPolicyRevalidationResultV1.target_observation_performed` is
bound into the current-evidence hash. It is `false` for every pre-observation
denial and whenever fresh target capture fails; in those results, the carried
baseline fields are projection-only and make no current-state claim. It is
`true` only after one successful fresh target capture. Successful capture uses
one byte read plus pre/post stat. Every discovered AGENTS candidate is observed with
lstat/stat/resolve before, one binary read, then lstat/stat/resolve after;
device/inode/size/mtime-ns, resolved path, and symlink target must remain stable.
A candidate that disappears after discovery, becomes unreadable, is replaced,
or resolves outside the workspace fails closed and is never silently omitted.
Stable path identity and content are deterministically bound into
`agents_policy_hash`; a candidate absent at the initial lstat remains canonical
absence rather than an invented policy file.

Revalidation compares retained subject evidence with the authorization
evidence, actual normalized arguments and operation, exact bound member, and
grant. It distinguishes AGENTS drift before target-state drift, then reruns
policy and the remaining Job Token/path/command checks. Snapshot, binding, and
revalidation denial tests install one shared fail-fast matrix over Director
tool execution/write/edit/delete, AgentAccel construction/execution, default
skill installation, KFS mutation, command services, os exec/spawn/fork,
subprocess, asyncio subprocess, and multiprocessing entrypoints.

This invalidates prior Task 1 contract-green evidence for the affected result
shape, frozen/slotted/type invariants, aggregate/component consistency, and
hash/member binding. Task 1 may be re-closed only after the focused contract and
static gates are rerun with this amendment. This is strictly Task 3's adapter
contract correction: it does not widen into Task 4, Task 9, DEO-3, metadata,
catalog work, or Bench.

## Canonical data flow and failure boundaries

For every batch:

1. `RoleRuntimeService._validate_session_execution_attempt` validates the
   process-local authority and TaskRuntime identity before request creation.
2. Classify every call exactly once as `mutation_capable` or `read_only` using
   the canonical ToolSpecRegistry effect classification. WRITE, ASYNC, and
   unknown/default-write are mutation-capable.
3. Read-only calls do not invoke DEO mutation preflight. A uniform caller may
   receive `DirectorEffectPreflightResultV1(status="not_applicable",
   applicability="read_only")`; this is successful and has no error, intent,
   grant, or authorization evidence. Read-only-only batches retain the existing
   raw `executor(tool_name, arguments)` path and make no DEO lifecycle calls.
4. Only mutation-capable calls run existing alias/argument normalization and
   role allow-list. Build the prospective operation subject, then obtain a
   no-effect policy snapshot through the injected adapter public port. That
   sole implementation evaluates path/command scope, strict mutation guard,
   Job Token restrictions, Director policy, current target state, and AGENTS
   policy. Freeze the successful result and run pure DEO preflight to derive
   ordered inventory intents.
5. Heartbeat the TaskRuntime authority. Enroll/admit and seal the complete
   mutation inventory, bind each pre-seal policy snapshot to its actual sealed
   TaskRuntime member, then admit every member and finalize readiness before
   dispatching any call in a mixed batch.
6. Immediately before each mutation, heartbeat again, claim by exact call id,
   construct/register an immutable execution context, validate the nested grant,
   call the same policy port's `revalidate`, consume once, and call the private
   physical executor. Revalidation denial leaves the fence unconsumed and causes
   zero effect for the current and later calls.
7. Read calls in a mixed batch may run only after the mutation inventory is
   ready. They remain grant-free and use the raw executor.

A classification, authorization, heartbeat, enrollment, seal, member
admission, or ready-finalization failure occurs before dispatch and therefore
guarantees whole-batch zero effect. A per-call claim, revalidation, fence, or
physical denial guarantees no dispatch for that denied call or any later call;
it does not roll back effects from earlier successful calls. DEO-3 owns later
reconciliation.

## Fence, lifecycle, and nested grant invariants

The one underlying process-local fence is created with `creator_pid=os.getpid()`
and a bounded capacity of 64. Registration binds the exact context object plus
creator PID, attempt stable identity, parent binding, operation, member,
inventory hash, grant hash, call id, and canonical context digest under one
lock. It retains a strong reference until cleanup. Consume requires the same
object and every binding, then atomically spends it. Registration, consume, and
cleanup all compare `os.getpid()` to creator PID; a fork child returns
`deo_fence_pid_mismatch`. The fence can narrow a grant but cannot issue,
refresh, persist, recover, or validate TaskRuntime state.

For a mutation batch, lifecycle order and actual TaskRuntime commands are:

1. `EnrollDirectedEffectParentRegistryStreamCommandV1(execution_attempt)`;
   require `parent_registry_stream_enrolled`.
2. `AdmitDirectedEffectParentCommandV1` with canonical `workspace`, integer
   `task_id`, exact attempt, `ParentCorrelationV1(turn_id, batch_id)`,
   deterministic admission key, `expected_version=0`, `expected_seq=1`, and
   `actor="roles.kernel"`; accept only exact admitted/replay binding.
3. `EnrollDirectedEffectOperationStreamCommandV1(execution_attempt,
   parent_binding)`; require `operation_stream_enrolled` and exact binding.
4. `SealDirectedEffectInventoryCommandV1` with ordered 1..64 intents,
   `expected_registry_version=parent_binding.registry_version`,
   `expected_registry_seq=registry_version + 1`,
   `expected_operation_head_seq=0`, and actor; require exact sealed projection.
5. For every sealed projection member, call the injected public policy port's
   `bind_member` with the matching successful pre-seal snapshot. Require exact
   ordinal/call/tool/effect-mode/fingerprint correspondence and store only the
   frozen bound snapshot. Binding failure occurs before member admission and
   produces whole-batch zero effect.
6. Admit every projection member in order with
   `AdmitDirectedEffectOperationCommandV1`: base workspace/task/attempt/binding,
   member call/effect ids, `expected_version=0`, next returned operation-stream
   sequence, actor, intended-effect fingerprint, policy-verdict hash, and
   expected-receipt-binding hash.
7. `FinalizeDirectedEffectInventoryAdmissionCommandV1` with exact inventory
   hash, latest returned registry version/next sequence, latest returned
   operation head, and actor. Require ready, no missing/unexpected ids, and
   exact ordered member equality.
8. Immediately before each mutation, heartbeat and issue
   `ClaimDirectedEffectCommandV1` with the same base identity, member ids,
   admitted operation version, next returned stream sequence, actor, and the
   member's three hashes. Accept only `ok`, `code="effect_claimed"`, version 2,
   and one exact grant. `idempotent_replay` has no grant and never dispatches.

Grant validation uses only the real nested fields:
`grant.execution_attempt`, `grant.parent_binding`, `grant.operation`,

their canonical `float.hex()` string and reject NaN and both infinities before
publication or hashing. Thus map and sequence payloads with visually similar
contents cannot collide.

`capture_effective_spec` reads one `_ToolSpecRegistryStateV1` reference, validates
that raw canonical specs materialize to the same effective canonical ToolSpecs,
that canonical-name membership matches both views, that every alias target
exists, and that every effective alias lookup agrees with the explicit binding.
Any mismatch raises `ToolSpecRegistryConsistencyError` before returning data;
the classifier maps it to `deo_tool_normalization_failed`. It must never select
raw or effective state as a fallback truth.

Inside the owner boundary, capture deep-copies then recursively freezes the
effective canonical spec plus complete canonical-name and actual alias-binding
views. `CapturedToolSpecSnapshotV1.__post_init__` recursively rejects any nested
`dict`, `list`, `set`, `bytearray`, untagged tuple, non-finite float, or invalid
tag/type pairing, rejects noncanonical map ordering/duplicate keys, and
recomputes all four domain-separated SHA-256 hashes from the tagged
deterministic UTF-8 canonical encoding via `object.__setattr__`; no
caller-supplied digest is accepted. Shallow-copy mutation after capture cannot
change the snapshot. Tests include map-versus-sequence collision attempts and
NaN/positive-infinity/negative-infinity rejection.

Public compatibility accessors retain their existing signatures but never
return owner-owned objects. `ToolSpecRegistry.get()`, `get_all_specs()`, and
every schema/OpenAI projection return detached deep copies. A returned
`ToolSpec.parameters`, `aliases`, `arg_aliases`, or nested value may be mutated
by legacy callers without changing owner state; `ToolSpec.to_openai_function()`
also returns a fully detached nested graph. No schema output caches or exposes
an owner-owned mutable reference.

Tests mutate the original registration input after registration and mutate
nested values returned by `get()`, `get_all_specs()`, and
`to_openai_function()`; every subsequent owner capture and hash remains
identical. They also cover duplicate canonical re-registration before/after
state hashes, alias-only binding/rebinding, ContextVar registry A/B isolation,
and deliberately corrupted raw/effective/canonical/alias state. Every
inconsistency fails closed without partial state.
