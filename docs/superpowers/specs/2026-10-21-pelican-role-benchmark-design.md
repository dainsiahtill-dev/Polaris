# 鹈鹕骑自行车：内部专项 Bench

2026-10-21。用户新增的专项评测，沿现有 EngineeringRunService / native acceptance / Instance Supervisor；不改变原120项目录或生产工作台语义。

## 目标与交付

固定题目：`Generate an SVG of a pelican riding a bicycle.` 每次由 Polaris 合法工具在全新隔离 workspace 生成 `pelican.svg`，交付可独立离线渲染的矢量图。外部工程 Agent 不画参考答案、不写或修目标 SVG、不装依赖或补原生收据。最终保留原始 SVG、版本指纹、真实最终请求/工具/验证/QA、浏览器 PNG、主 Agent 视觉结论与资源关闭结果。

研究问题是同模型、同权限、同预算下，角色组合和实际交接链是否改善图像的结构、空间组合与交付效率。单个著名题目不能证明整体工程开发最优、ContextOS 优势或未见组合泛化。原题公开已久，训练污染未知；日后变式单列，不作为本次前置。

## 机制与范围

1. 独立 `projects_pelican_v1.json`，单案例 `VIS-PEL-01`；原 `projects_v2.json` 仍为120项、SHA256 f8a1af935a9b58d49a099453180a73175abc4a6fedf10917c10cb92609771af3。
2. 固定纯SVG要求、host及机械检查放现有内部 Bench fixtures。正式启动直接构造既有 LaunchInputs 或使用 engineering_acceptance CLI，传外部冻结输入；不调用软件PRD生成器。该生成器总会加入 README、源码拓扑、代码行数和软件测试义务，不适用这次单SVG任务。
3. host延续5400秒工程预算/6000秒总守护，QA=true；read/write只在workspace，network=false，复用现有通用工具，verification_output_roots显式为空。模型沿当前MiniMax-M3配置并冻结hash。完成即结束，无需耗尽预算。
4. 五组各两次，固定随机顺序，严格串行：D独立；D咨询PM一次；D咨询CE一次；真正原生collaborative的PM、CE、D；D按需咨询。固定组不补调用；实际偏差保留按分配分析，不替换样本。普通失败继续原执行循环，不重规划合同。
5. 原生collaborative直接复用既有owner，PM完整文本进入CE，PM/CE完整文本进入Director；不是用D自行摘要的咨询冒充该链。其他组沿direct，模型自主工具循环。最终请求和持久角色事件核对实际链。
6. 所有组收到相同原题和操作约定；角色指令只说明谁处理，不给某组额外解题几何提示。没有事先文档配额；方法、文件数、代码行数、圆形/路径数、模型自述不计视觉质量。

## 验证与评审

机械检查只证明SVG真实落盘、XML/namespace有效、自包含、无脚本/外部资源/嵌入raster，浏览器实际渲染并有可见内容。它不能证明图像中的物体和空间关系。

主 Agent 每次原实例关闭后亲自查看同一候选的实际渲染，评四项0–4：鹈鹕辨识与结构、自行车结构、骑行空间关系、构图清晰度。保留文字证据与关键错误，0–16仅描述，不新增分数门禁。鸟车分离、不是可辨识鹈鹕/自行车、严重裁切或无实际画面不能被装饰分抵消。允许风格化、透视和遮挡；不强制两腿可见、特定颜色或SVG元素。

评测者只观察，不向计分运行回灌修图建议。当前工程工具返回文本，尚无证实的渲染图像进入provider请求路径；本轮不宣称原生视觉自修复或视觉QA。独立原生QA、机械检查与外部视觉评审分开报告。

主 Agent 调度且逐例验收，初评并非完全盲法。完成后可对匿名图做20对标签隐藏比较（每重复五组十对），可能仍有图像记忆；不声称双盲或统计显著。缺失图保留不可评状态，不能删除失败、虚构图或补跑择优。

## 实验终点与证据

首轮10次或已知预算终点结束；每例资源确认关闭、主 Agent评审完成后才运行下一例。未知效果/资源未收口先停新增，保留UNKNOWN，不盲重放。源码或配置改动另起版本。

记录所有已尝试/未跑、失败、取消、超时、真实链、输出/当前QA、机械/视觉结果、启动/执行/评审时间、原与辅助资源；prepared capture及快照不冒充HTTP发送数，账单未知保持UNKNOWN。

旧角色试验第1次L1-02：原生accepted/资源闭合，亲自质量FAIL；剩余9次未跑（第2次仅外部输入已准备），按用户新方向转入本专项。原120项验证任务仍保留，不把专项重复计为原目录覆盖。
