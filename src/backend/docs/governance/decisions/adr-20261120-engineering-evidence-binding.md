# 工程验证与终态对账

## 决策

现有 EngineeringRunService 继续持有活跃 workspace 的源码写锁。EngineeringSessionStore 在同一事务内核对候选 revision、验证 attempt 与运行状态。迟到结果追加历史事件。显式恢复在原权限、deadline 和 workspace 锁下执行。未知写入只允许宿主对原调用做有界读回，读回和原始未知效果各自保留。

QA 的条款记录来自当轮实际观察。新完成事件记录 frame、turn、call 和 event 的身份。旧记录只有在其 frame 与 call ID 能定位唯一成功观察时才用于批准。候选、宿主契约、验证器实现、声明环境和可用的独立夹具分别绑定。环境指纹覆盖的字段列在物理记录中。

## 影响

旧 runs 数据按原身份只读。部署更换验证器后，带新证据绑定的历史 pass 仍可查询；同候选的当前验收需要通过新验证器。SQLite 会话继续提供角色、观察和验证事实。ContextOS 展示与实验的派生信息不参与授权。

正常入口回归需要覆盖同一命令的两次执行、候选在验证中变化、终止后迟到回执和中断写入后的恢复。实际验收另需核验原始目标、候选产物、运行资源清理与独立效果。
