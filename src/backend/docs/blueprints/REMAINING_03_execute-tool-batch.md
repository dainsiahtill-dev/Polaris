## risks
- NONDETERMINISM SENSITIVITY: weak-Director memory entries reference this function; several branches (content_gathered gate, from-scratch trap, exploration_streak) were tuned against live benchmarks (factory-bench L2-11, L3-16, run10a, run20). A subtle reordering of a predicate (e.g., evaluating exemption after the gate instead of before) changes which RuntimeError fires and thus which retry ladder the orchestrator takes. Mitigation: extract as PURE predicates that return verdicts; keep ALL raise/log/emit sites in the orchestrator in unchanged order.
- EVENT ORDERING: `_raise_contract_violation` emits an ErrorEvent BEFORE raising. If a predicate is made to raise internally, the ErrorEvent emission moves and tests asserting (event sequence) break. Mitigation: predicates return ContractDecision; orchestrator owns emission.
- LEDGER MUTATION ORDERING (ADR-0071): tool_batch_count is incremented at line 1076 (before authoritative execution) and decremented at line 1403 (argument-shape void batch). guard_assert_single_tool_batch fires immediately after increment. Moving the increment or the guard relative to extraction would let a second ToolBatch slip the single-commit invariant. Mitigation: keep increment+guard+decrement co-located in orchestrator; never push into a helper.
- PRIVATE PHASE-MANAGER ACCESS: code reads ledger.phase_manager._turns_in_current_phase / _max_turns_per_phase (private). A PhaseSnapshot helper must read the SAME private fields, not a public accessor that might differ. Mitigation: snapshot copies the exact private reads verbatim.
- invocations REBINDING: lines 650, 675, 679, 936-959 rebind the `invocations` local (path rewrite, edit_blocks fill, out-of-scope filter, implementing-phase partial block). Downstream gates use the LATEST binding. An extraction that captures invocations by value too early would gate on stale data. Mitigation: helpers receive invocations as parameter at call time; compute flags AFTER all rebinds.
- SHADOW-ENGINE LOOP COMPLEXITY: the adopt/join/replay/block + write-tool fallback + adoption-audit block (1119-1247) has 4 distinct control-flow exits per invocation and an audit sub-call that must safely degrade. Highest regression risk. Mitigation: extract last, with characterization tests for each action (adopt-readonly, join-readonly, adopt-write→replay, block-write→replay, spec-error-write→replay, audit-mismatch→authoritative).
- DUPLICATE COMPUTATION: latest_user_message is extracted 4x (668, 696, 1297, 1473) and tool_names 2x (773, 971). Consolidating into one variable is tempting but `extract_latest_user_message` could (in principle) be non-pure across the executing window; behavior-preserving refactor must NOT consolidate these reads unless proven idempotent. Mitigation: keep separate calls or prove purity first.
- BENCHMARK BYPASS DIVERGENCE: barrier bypass (line 699) and phase-transition bypass (line 1299) BOTH key on '[Benchmark Tool Contract]' but compute it from separately-extracted latest_user strings. Keep both detections; do not unify into one snapshot unless the two latest_user reads are proven identical at both points.

# G5 — Hot Transaction Kernel: Behavior-Preserving God-FUNCTION Decomposition Blueprint

## 1. Why this is the highest-risk decomposition

`execute_tool_batch` is the single authoritative TOOL_BATCH executor and the single commit point per ADR-0071. It inlines the entire phase/barrier/exemption decision tree with ~15 dated `FIX-*` blocks and `BUG-NEW-1/2` markers. Multiple weak-Director memory entries and live benchmark runs (factory-bench L2-11, L3-16, run10a, run20, phase1smoke4) tuned individual branches. Any reordering of a predicate changes WHICH `RuntimeError` fires, which changes WHICH retry ladder the orchestrator (`retry_tool_batch_after_contract_violation`) takes — a behavioral change even if no test breaks. The decomposition is therefore **predicate-extraction only**: helpers return verdicts; the orchestrator keeps every `raise`, `emit_event`, and `ledger` mutation in unchanged order.
