# Roles Runtime Cell

## Current engineering owner

`EngineeringRunService` in `public/engineering_service.py` owns all new engineering execution, observation, cancellation and recovery. HTTP/CLI/UI adapt to that public owner. Direct Director is default; explicit collaborative work runs PM, Chief Engineer and Director through the same service. Read-only consultation returns one level; discussion has no action tools and creates no run. Uncalled roles remain `not_called`.

## State and boundaries

The single new-run fact store is `<workspace>/.polaris/runtime/engineering/sessions.sqlite3`; `engineering_session.py` persists runs, events, tool observations and verification, with `engineering/workspace.lock` enforcing one workspace writer. `runtime/engineering/*` in the manifest is relative to the canonical workspace runtime root, not a second physical runtime directory.

`public/contracts/engineering_run.py` exposes `RoleRunCommand`, `PermissionScope`, `RunLimits`, `ToolObservation`, `RoleRunResult`. These are program interfaces, not model-authored business contracts. Cross-Cell consumers use public boundaries; internal modules below belong to this Cell.

- `engineering_loop.py`: ordinary native-tool/model loop.
- `engineering_tools.py`: normalized technical tools with host permission and sandbox enforcement.
- `engineering_roles.py`: role identity, ordinary-text advice and read-only consultation.
- `engineering_browser.py`: K1-isolated local rendering and atomic public DOM click/keypress/fill/select_option sequences. Literal values, including legal empty strings and spaces, remain exact; standard-control observations expose bounds/truncation. Existing host deadlines, total wait/frame/wire bounds, read/network isolation and cancel/drain remain. Each call starts fresh; no cross-call browser state or download artifact is promised.
  Optional capture-only `web_root` provides a contained static HTTPS origin for ordinary local assets/ES modules/CSS through existing Playwright route fulfillment, without a server or target rewrite. Host read grants, root containment, GET/HEAD, hidden/link/URL rejection and existing OS sandbox remain authority. Target resources use the canonical KFS guarded snapshot implementation via the public fixed runtime-source port; no backend mount or duplicated guard. Per-resource16MiB/total64MiB allowance includes HEAD; failed uncertain reads retain reservations, so `bytes_read` reports only successful snapshots. Historical capture arguments are registry-normalized before current scope checks on revisit; saved pixels/bindings never become fresh.
- `engineering_working_state.py`: request-only QA observations derived from the existing run row/journal; no persisted state or execution authority.
- `engineering_verification.py`: real checks against the current source candidate.
- `engineering_session.py`: durable observations, committed events and workspace execution lock.
- `engineering_visual.py`: derives visual model input from the same journal. A complete same-role host capture binding can omit obsolete browser pixels while preserving their metadata, tool results and original stored images. All current capture sets, original user references and unattributed inputs remain; verification receipt sequence alone does not make an image stale. The existing budget may omit optional historical image payloads while retaining durable results and exact original pixels. `browser_observe(revisit_call_ids=...)` retrieves this role's same-session captures without refreshing their candidate binding; capture and revisit arguments are exclusive. Public cross-session retrieval is not provided.

The internal event reader supports optional kind/role selection in the existing SQLite query. Default reads retain the full journal; matching history is never truncated. Visual attribution, native turn checks, review binding and tool reconciliation consume their required kinds without decoding auxiliary requests. Selected payload errors still fail; a filtered read is not a whole-journal health check. This adds no cache, schema, event deletion or execution authority.

For Director requests with an existing run deadline, a transient user message at the end of the complete request-only view observes that saved deadline, preparation wall-clock and approximate remaining seconds. Native codecs may merge adjacent user content; original system, earlier content, tool pairing and images remain intact. The observation is rebuilt per request and never appended to durable conversation history. PM/CE and absent-deadline Director keep the original input. QA receives the separate factual observation described below. This changes no actual timeout, output cap, retry, permission or completion policy. Preserving earlier prefix content does not prove cache hits or delivery benefit. Fresh-service recovery reuses the original persisted deadline, without claiming a new-process crash experiment.

QA requests append one transient factual user message observing the current candidate, current QA role frame, successful source reads/own captures, report observations, last exact-argument/result and same-visible-result counts, and saved deadline/preparation remaining time. Counts reset at the actual candidate/frame boundary. Equal visible output with different arguments does not prove identical commands or effects. Unknown deadline remains unknown. This message is rebuilt from the existing journal and is absent from durable conversation history; it adds no retry rule, forced review or acceptance shortcut. The fixed four-request pilot had a changed next-tool proposal for L1-02 and no improvement for L1-01; full QA convergence and delivery benefit remain unverified.

No second controller, task table, ledger or role-session mirror is created for new runs. Legacy `runtime/roles/*` remains declared only to explain old owned history; it is not a writable namespace for engineering.

## Permissions and effects

Host `PermissionScope`, saved limits/deadline and current permission policy govern effects. Explicit empty roots/tools remain empty. Text advice cannot expand grants. File tools use KFS and real-path/symlink/root checks; command tools require actual OS containment and process-tree drain. PM/CE/QA are read-only by default. Unsupported containment fails visibly rather than executing unsandboxed.

Host-only `toolchain_bin_dirs` declares additional executable directories in order after K1's fixed system PATH. It never discovers paths from read grants or inherits host home/PATH. K1 resolves them inside existing directory read mounts, excluding control/private roots, PATH separators and writable overlaps; it adds no mounts or write/network authority. The existing engineering owner carries this optional scope through host settings, saved permissions, role scopes, verification and cold recovery. Missing/empty historical values stay empty, with the original scope/binding encoding preserved; current policy may revoke directories but cannot silently add them to an old run. Persisted history must remain readable when a toolchain later disappears. Earlier toolchain qualification recorded740 combined checks, K1 ALL, architecture/catalog and independent review, plus one actual installed-Go compile through cold scope and Verifier. Component evidence does not establish native delivery or cache persistence; its14745-input binding overhead remains measured and unoptimized. See the [design](../../../../../../docs/blueprints/POLARIS_HOST_TOOLCHAIN_BINDING_20261023.md).

When the host grants `execute_command`, QA may use it for independent checks with no workspace write roots and no network. Each command gets K1's existing private temporary space; it cannot persist checker code or change candidate/dependency inputs. PM/CE still do not acquire this execution capability. Availability does not prove that QA selects useful checks or judges their results correctly.

For service-owned native tools and final verification, the existing owner rechecks saved grants against current host policy after normalization and before each effect. A revocation denies the next effect with a real failed observation; it does not retroactively cancel an already running command. Explicit standalone components without a policy resolver have their static supplied scope, not a dynamic revocation promise. Offline commands with no effective write roots preserve the candidate revision; commands with possible writes or network retain conservative verification invalidation. Unknown effects still block recovery and acceptance even when the supplied scope was read-only.

`fs.write:workspace/**` in the graph declares effect kind, not ambient authorization: each operation still needs the saved host grant. Engineering state writes stay under `runtime/engineering/*`; provider requests, tools and durable observations are auditable. KernelOne provides provider/native codecs, ToolSpec aliases/arg aliases, KFS/storage, sandbox/process and budget primitives, without importing the old business execution protocol.

## Verification, QA and recovery

Director consumes ordinary build/test/tool failures within the same run. Declared checks remain required; when omitted, Director selects checks from the actual project and runs them. Model completion, empty checks, ordinary successful command output and QA prose cannot independently produce accepted. Final verification binds current source; required independent QA reviews that same candidate and rejection returns to the same task. Host writable output declarations are permissions for future paths, not required deliverable directories. Each verification attempt validates every original declaration, then freezes only existing real directories as effective writable mounts; queries never create them. Missing directories allow genuine read-only checks. A write requiring an absent directory fails inside the same containment; Director can prepare it using original tools and the next attempt recomputes the subset. Candidate observation revalidates even declarations absent at attempt construction. Source/output replacement invalidates prior verification and QA; cold recovery keeps original saved declarations and explicit empty grants. With mandatory independent QA, Director may hand off after actual current checks without a separate mandatory Director image finalization. Its visual tools and discretionary inspection remain available. Without mandatory QA, a host-required Director visual review still needs its own current image consumption. QA independently reads source and inspects its own current captures in the actual later provider request before approval. Snapshot/observe and cold service reads consume this same saved QA policy; neither constructor defaults nor missing Director pixels demote valid independent QA. This routing qualification does not establish model quality or delivery improvement.

Known transport HTTP5xx failures use an optional KernelOne `InvokeResult.error_category` and the existing AIExecutor request resilience owner. The shared helper still performs no local5xx backoff; the native outer policy and original attempts/timeouts remain. Explicit host retry-category restrictions stay binding. Final provider metadata records the actually selected caller policy independently of model metadata; it does not enter the model body. Old absent categories/snapshot policy remain unknown. Local real-HTTP qualification proved529/200 recovery within outer1/inner2 and one prior tool effect, not upstream health or native delivery. See [the evidence and boundaries](../../../../../../docs/blueprints/POLARIS_PROVIDER_RETRY_DELEGATION_20261024.md).

Recovery preserves run/workspace identity, original permissions/checks/deadline and revalidates current host policy. Unknown write or command effects remain interrupted/UNKNOWN until reconciled; never blindly replay. Cancellation is not complete until process containment and drain are known. Old run IDs are never imported into engineering identities.

## Realtime and final request audit

Committed engineering facts publish as `event.engineering` through the existing Nats-JetStream runtime.v2 `/v2/ws/runtime` rail; HTTP serves initial/reconnect snapshots, explicit refresh and one-shot commands. No polling/SSE fallback or second WebSocket. ContextOS exposes actual final provider requests with role/tool schema/tool_choice/response_format/token/window evidence and readable same-workspace snapshot refs. Persisted request/snapshot counts are not physical provider HTTP totals or billing evidence.

The existing `request_prepared` event records derived visual selection counts and attribution reasons. It is auxiliary input-production evidence, not a sent provider body. KernelOne budget and native protocol guards still decide admission; required/current/reference content that exceeds the budget remains an explicit failure. Serialized estimates are not actual visual token costs. This projection does not restore the retired StateFirst/TurnEngine business chain.

## Historical compatibility and optional utilities

`public/service.py`, old DTO exports and declared dependencies on role/kernel/session/task-market/Factory cells describe retained historical readers, serialization and explicitly optional utilities. Their presence is not new-run admission. Legacy writable `RoleRuntimeService`, `execute_role_session`, `RoleExecutionKernel` and Factory protocol paths are retired for new execution; old in-flight runs remain on their original frozen owner.

The new loop never falls back to PM contracts, CE portfolio/hash/semantic patches, JobToken/DEO/Run Ledger gates or automatic deterministic repair schedules. Explicit independent repair utilities may remain in `director.runtime` public, with coverage/policy/receipt/revalidation; they are not prerequisites for ordinary compiler-error repair. Historical code has not all been deleted, and graph metadata must not claim otherwise.
