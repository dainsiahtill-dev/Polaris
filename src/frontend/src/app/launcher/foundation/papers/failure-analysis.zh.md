# 失效模式与架构收敛：安全性之外还要可继续

这些是封存执行与源码反例，说明跨层假设如何阻断工作。它们不是性能对照实验，也不证明所有模型或所有项目的整体能力。

## 上下文位置与预算不同

完整源码曾被放入受保护的当前用户指令，而该字段上限为 8k。角色模型整体窗口可以更大，但字段仍先失败。修复采用现有独立证据消息，让用户目标、完整源码、CE 蓝图和验证数据各自保持正确角色，不上调指令上限来掩盖装配错误。

该案例证明容量、证据覆盖和装配位置需要分别验证。后续 prepared request 检查是组件证据，尚不能代替独立 QA 真正发到 provider 的最终请求与判断。

## 子任务完成，但外层验收失败

Director Task1 已 completed，外层 QA 却可能在请求前失败。早期清理判据只接受最新失败任务或失败命令，未进入严格效果闭合检查，导致已经终止的运行保留租约。修复仅在原始 canonical 失败生命周期事件精确匹配后进入原有严格检查，仍保留验收失败与缺失证据。

失败资源可以释放，项目仍不通过。不能通过把 completed 任务改成 failed 来凑进入恢复路径的条件。

## 正式移除之后恢复原拥有者

正式清理保留计划并移除 live task/session。后继恢复原先只接受 failed/cancelled，拒绝合法 completed-reset。修复用准确的 terminal event ID、序号、transition、outcome、合同与 old owner proof 找回原 numeric task，再走正常 fresh claim。历史完成事实没有改写，新执行也没有伪造旧会话。

完整私有 Factory 回归与实际后继执行分别证明了这一边界。组件成功只覆盖该恢复机制，不能外推后续验收必定完成。

## 推断命令与合同命令不同

只运行 npm build/test/start 不能代替全部 CE signed argv/cwd。改变可变 package script，让某个旧产物入口能启动，也不证明 CE 的声明入口已生成。当前 VerificationGroup 使用干净 authored inputs 运行完整义务，真实暴露了声明入口缺失：环境、构建、类型检查、测试可结束，而 exact ENTRY 仍为非零。

这些中间观察为真；在整组没有完整 seal 和当前 proof 前，它们不是全部验收 PASS。独立语义 QA 也不能凭自测通过忽略原始需求、接口或行为差异。

## 回合提交被总历史容量限制阻断

封存 roles.kernel.turn_outcomes 日志为 8,354,716 bytes、47 条记录；strict append 配置为 8,388,608 bytes，余量 33,892 bytes。已有末条记录为 552,213 bytes。这个末条大小不是被拒的新帧大小；未提交 encoded frame 的精确尺寸没有封存，本文不推断它。

确定的机制是：追加端比较整个文件长度加新编码帧，读取端已按单帧与页校验。累计历史容量到达边界时，单条本来合法的后继记录会被拒绝。已经返回工具观察，不能因此声称 OutcomeCommit 成功。此问题仍未实施修复。

## 调用日志和真实请求证据之间仍有缺口

本次后继质量修复留下 7 对角色调用开始与结束记录。对应普通快照能证明规范投影存在，但没有完整最终 wire body/hash；不能把角色调用数当成已验证的物理请求数，也不能把缺 wire 当成没有调用。

平台有 Factory 治理型 wire gate 和显式 role_session gate。问题应检查每个调用是否实际安装和传播它们，而不是宣称能力不存在或所有调用天然已被覆盖。

## 收敛原则

保留明确状态拥有者，统一跨层身份与证明契约；让普通产物失败回到原执行拥有者；从最新输入和最新义务修复；独立验证后继续任务；让资源闭合与结果接受分别投影。必需证据和权限边界继续有效，存储、防护、观察与恢复的预算则应与长任务的合法生命周期匹配。

最重要的验收是从最初需求到当前产物、真实命令、独立 QA、多拥有者结果和正常释放的一次完整闭环。当前材料还没有这个最终成功结果。
