# 非默认能力与研究性组件

仓库里有实现、存在公开接口、某次执行启用了它、它带来了可重复的收益，是四个不同断言。这里按实际接入证据分类，不以模块名称、UI 卡片或构造函数的默认参数作为运行证明。

## 默认主链中的上下文能力

StateFirst 默认使用普通七阶段 PipelineRunner，并组合结构状态、活动窗口、ProjectionEngine、内容引用和角色补充信号。ProjectionEngine 的自适应反馈是进程内规则或评分窗口，不是模型参数训练。

## 按条件消费的能力

| 组件 | 有什么实现 | 接入限制 |
| --- | --- | --- |
| ContextOS MemoryManager | 会话快照候选、Jaccard 相关度、时间与规则冲突检查 | aggregate 条件路径；不同于 Akashic MemoryManager，不能称完整 embedding RAG |
| Akashic | 分层工作记忆、情景和语义存储、可选向量检索、压缩 daemon | 需要显式初始化与生命周期；默认角色 daemon 接入未由本研究证明 |
| Knowledge Pipeline | 抽取、切块、丰富、embedding、幂等入库 | 入库和当前角色召回是两步，memory_id 不证明模型已看到原文 |
| Resident | workspace 服务、显式 start/stop、tick、insights 与 proposals | 默认 inactive；提案不接管效果权威，也不等于自动在线训练 |
| AGI repair advisory | 建议标准化与资格投影 | 建议不能写文件、注册规则、生成权威计划或给验收结论 |

## 未证明默认构造的增强组件

EnhancedPipelineRunner 有 phase、attention、graph、memory 与 predictive 组合；默认 StateFirst 当前选择普通 Runner。IntelligentCompressor 及部分内容 crushers 存在实现，也不能替代默认 CompressionEngine 的实际路径。WorkingSetAssembler 描述仓库地图、符号和代码切片，但其存在不证明 UI WorkingMem 已使用它。

Neural Syndicate 的 OrchestratorAgent、broker、blackboard 与可选 critic consensus 是另一组协作库。当前读到的构造器与 CodeGraph 关系没有建立其作为 PM→CE→Director 主调度的接入证明。BlackboardClient 的基本 KV 是进程内字典，TTL 参数注明未实现；产物持久化需要注入 ArtifactServicePort。资源配额的默认 100 只是配置，本文没有做 100 Agent 并发实验，也不把 confidence 合并当作项目验收。

## Cognitive 与可复现评测模块

认知、intent graph、推理、感知、evolution 与 holographic 相关包需要逐条查看实际调用点。部分能力位于内部评测或测试目录，服务于复现、评价与模拟；它们没有因为名字独特就变成生产中的自我意识、常驻规划或自主研究能力。

## 如何证明某扩展确实工作

需要实际构造与依赖注入证据、当前实例的启用配置、从主调用路径进入它的调用、结果如何被消费，以及相同条件下的失败与收益观察。只有这些证据齐全，才适合把该能力写成当前默认行为。
